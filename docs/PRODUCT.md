# PRODUCT — 产品设计文档

## 1. 一句话定位

> 让用户在真实英文环境中阅读，通过 AI 把遇到的语言障碍，转化为可以长期复利的个人英语知识资产。

## 2. 我们在解决什么问题

英语学习者（尤其是程序员和技术从业者）每天都在读英文，但**读的过程和学的过程是断裂的**：

1. 读技术文档遇到生词 → 划词翻译 → 看到一个词典义 → 关掉 → 三天后再遇到，再查一遍。
2. 词典义经常是错的**语境义**：`migration`、`socket`、`primitive`、`degrade`、`ship`
   在技术语境里的含义和通用词典释义差别巨大，而翻译插件不知道你在读什么。
3. 想认真学的人会手动往 Anki 里抄单词——抄的过程丢掉了最有价值的东西：
   **你是在哪句话、哪篇文章里遇到它的**。

现有工具各自解决了一段，没有一个工具把它们连起来：

| 工具类型 | 代表 | 解决 | 缺口 |
|---|---|---|---|
| 划词翻译 | 沉浸式翻译、read-frog | 读得懂 | 读完即弃，无资产、无复习 |
| 词典 App | 欧路、有道 | 查得到 | 与真实阅读场景割裂，没有上下文 |
| 记忆软件 | Anki | 记得住 | 需要手工造卡，且卡片没有来源语境 |
| 通用 AI | ChatGPT | 解释得好 | 要切换应用、复制粘贴，无沉淀 |

**我们的机会：把"读 → 懂 → 存 → 记"压缩进一次划词。**

## 3. 目标用户

**主要用户**：中文母语、有一定英语基础（CET-4 以上）、需要长期阅读英文材料的技术从业者。

具体画像：
- 每天读 GitHub README / issue / 技术博客 / 论文 / Reddit / Hacker News
- 认识大部分单词，卡住的是**语境义、习语、和领域黑话**
- 有过"下决心背单词"然后放弃的经历
- 愿意为效率付费，但不想再多一个需要维护的账号

**次要用户**：备考、外企办公、读英文新闻的泛英语学习者。

**明确不是目标用户**：零基础学习者（他们需要的是系统课程，不是阅读辅助）。

## 4. 核心用户旅程

```
① 阅读                                                    在 GitHub 上读一个 Postgres 项目的 README
   ↓
② 卡住                                                    "Database migration can be dangerous."
   ↓ 选中 migration
③ 浮出小按钮 →（点击）→ 卡片                              不打断阅读节奏，卡片出现在选区下方
   ↓
④ AI 结合上下文解释                                        基础义「迁移；移民」
                                                          语境义「这里指数据库结构/数据从旧版本
                                                          迁移到新版本，不是人口迁徙」
   ↓
⑤ 一键收藏                                                连同原句、页面标题、URL、时间一起存档
   ↓
⑥ 单词进入复习队列                                         熟悉度 0（陌生），10 分钟后首次到期
   ↓
⑦ 闪卡复习                                                正面：migration
                                                          背面：释义 + 语境义 + 例句 + 当时那句原文
   ↓
⑧ 数据面板                                                收藏数、连续天数、熟悉度分布
   ↓
   回到 ①，形成复利
```

**这条链上每一环的价值都依赖上一环**，所以 MVP 必须一次做完整，而不是先做半条。

## 5. MVP 功能定义

### 5.1 AI 划词解释（P0）

| 项 | 设计 |
|---|---|
| 触发 | 三选一：选中后出现小按钮（默认）／选中即解释／按住 Alt 选中；另有右键菜单和 `Alt+Shift+E` |
| 输入 | 选中文本 + 所在句子 + 所在段落 + 页面标题 + URL |
| 输出 | 单词、原形、音标、词性、基础释义、**语境含义**、英文释义、AI 例句 + 翻译、近义词 |
| 交互 | 浮层永远不遮挡被读的那句话；Esc / 点击别处 / 滚动关闭；朗读；一键收藏 |
| 失败 | 明确错误原因 + 重试 / 改用离线词典 / 去设置，绝不留死胡同 |
| 成本 | 同一个词在同一句话里的解释默认缓存 72 小时 |

**质量红线**：语境含义必须真的回答"在这里指什么"。如果语境义与词典义一致，模型必须直说
"此处就是常见含义"，而不是编造一个区别——这条写进了 system prompt。

### 5.2 个人单词本（P0）

- 列表：单词、音标、词性、释义摘要、来源域名、收藏时间、熟悉度、下次复习时间
- 搜索：单词 / 中文释义 / AI 解释 / **原句** 全文匹配（"那个 Postgres 文章里的词"）
- 筛选：全部 / 待复习 / 按四档熟悉度
- 排序：最新 / 字母 / 复习顺序
- 详情：完整解释 + 来源原句与链接 + 手动调级 + 个人笔记 + 删除
- 导出：JSON（完整快照）/ CSV（给 Anki、Excel）

### 5.3 AI 闪卡复习（P0）

- 正面：单词 + 音标 + 朗读；提示"先想想它在原句里的意思"
- 背面：基础释义、语境含义、英文释义、AI 例句、**当时的原文**
- 四级自评：忘记 / 有点模糊 / 记得 / 完全掌握，每个按钮直接显示"下次什么时候再见"
- 熟悉度四档：0 陌生 / 1 学习中 / 2 熟悉 / 3 掌握
- 队列：弱的优先（等级升序），同级最过期的优先
- 键盘优先：空格翻面，1–4 打分

### 5.4 学习 Dashboard（P0）

收藏总数、待复习数、今日复习进度环、连续学习天数、近 14 天活跃柱状图、熟悉度分布、最近收藏。

**原则：只展示能从本地数据真实算出来的数字。** 没有"预计词汇量""学习力指数"这类无法证伪的指标。

### 5.5 设置（P0）

模型选择与 Key、触发方式、自动朗读、英文释义开关、最长划选长度、每日复习目标、缓存时长、
站点黑名单、数据导入导出与清空。**带一个真实调用的"测试连接"**，直接把模型返回的语境解释显示出来。

## 6. 设计原则

1. **上下文是第一性的。** 任何丢掉上下文的功能都不做。收藏时不存原句 = 没做这个产品。
2. **绝不打断阅读。** 浮层永远在选区下方（放不下才翻到上方），一次 Esc 全部消失。
3. **零配置可用，配置后更好。** 没有 Key 也能跑通完整闭环（离线词典），但离线模式**必须诚实**地
   说明自己无法结合上下文，绝不假装。
4. **本地优先。** 没有服务器、没有账号、没有埋点。数据随时可导出，导出格式就是未来同步的格式。
5. **失败要有出路。** 每个错误状态都给下一步动作。
6. **诚实高于漂亮。** 不编造音标，不编造释义，模型不知道就返回空。

## 7. 非目标（第一阶段明确不做）

| 不做 | 原因 |
|---|---|
| 全文翻译 / 双语对照 | 那是沉浸式翻译和 read-frog 的战场，做了会稀释"学习"这条主线，且成本高 |
| 服务端与账号体系 | MVP 不需要；本地优先反而是隐私卖点。同步用 GitHub 仓库解决 |
| 复杂 SRS（SM-2 / FSRS） | 几百个词的规模上，ease factor 没有数据可学，四档阶梯更好解释 |
| 移动端 / 其他浏览器 | 先在一个平台把闭环做扎实 |
| 社交、排行榜、打卡分享 | 与"个人知识资产"的定位无关 |
| 语法讲解、写作批改 | 是另一个产品 |

## 8. 成功标准

**第一阶段验收（功能）**：见 [TODO.md](TODO.md) 的验收清单——装上、划词、解释、收藏、单词本、
复习、刷新后数据仍在。

**产品意义上的成功（需要真实用户验证）**：
- 一个用户在装上两周后，单词本里有 ≥ 30 个词，且其中 ≥ 1/3 被复习过至少一次
- 用户能说出"我是在哪篇文章遇到这个词的"——说明上下文真的被记住了
- 用户愿意导出自己的知识库（说明他认为那是资产）

## 9. 后续方向（不属于 MVP）

- **GitHub 同步**：把知识库作为 JSON 提交到用户自己的仓库，形成"个人 AI 英语知识库"
- **段落级理解**：选中一整段 → AI 拆解长难句结构（而不是翻译）
- **主动发现**：基于单词本，在新页面上高亮"你收藏过的词"，制造重逢
- **阅读画像**：按领域/来源统计生词分布，告诉用户"你在分布式系统主题上的生词密度最高"
- **AI 生成复习内容**：用用户自己的词生成一段短文，替代孤立的卡片
