# 翻翻词卡 — Brand Guideline

> 「翻」：翻译、翻阅、翻页、翻卡。一个字，四个动作，都是产品里真实发生的事。

本文档是品牌与界面的唯一事实来源。它描述的每一个色值、字号和间距都**已经落在代码里**
（`src/styles/design-token.css`），并且由测试守着（`src/styles/tokens.test.ts`）。
设计文档与实现分家的那一刻，它就变成了考古材料。

---

## 1. 品牌是什么

**一句话**：翻翻词卡是一个陪你长期读下去的 AI 阅读伙伴。

**它做的事**：把你在真实英文里撞上的每一次卡顿，变成一条带着当时语境的词卡，
再按遗忘曲线送回你面前。

**它不做的事**：替你把英文变成中文然后消失。

这个区别决定了整套视觉：一个翻译工具可以张扬，因为你用完就走；一个陪伴工具必须**沉静**，
因为它每天出现在你正在读的那段文字旁边，而那段文字才是主角。

### 调性坐标

| 是 | 不是 |
|---|---|
| Intelligent —— 克制的智能感，靠信息密度而不是特效 | 炫技的科技感、粒子、故障风 |
| Calm —— 长时间阅读不疲劳 | 高饱和、强对比、跳动的动效 |
| Premium —— 细节经得起放大 | 廉价的圆角 + 阴影堆叠 |
| Companion —— 站在读者一侧 | 说教、成就徽章轰炸、拟人吉祥物 |
| Lightness —— 轻快 | 儿童教育风、游戏化奖励、低龄化 |

参照物：**Notion** 的克制、**Linear** 的密度与层级感、**Perplexity** 的 AI 气质。
Duolingo 提供的是"学习"这一属性的提醒，而**不是**它的视觉语言——它的受众是需要被哄着坚持的人，
翻翻词卡的受众是已经在读英文、只是想读得更深的人。

**中文名的已知风险**：「翻翻X」在中文图书市场是低幼翻页书的品类句式。名字保留，
但视觉必须把年龄拉回来——这是本文档后半程的全部任务：无插画、无吉祥物、无花哨渐变，
克制的几何加上冷墨底色。

## 2. 色彩

### 2.1 为什么是橙

四个参照产品在货架上的位置是：Notion 近乎无色、Duolingo 绿、Linear 紫、Perplexity 青。
**橙色是这排货架上的空位。** 紫—靛是当下 AI 工具里最拥挤的颜色，进去就等于自愿隐形。

橙也是纸页在灯下的颜色，和「翻开」同频；是温度和好奇，正好是遇见生词那一刻的情绪；
在中文语境里意味着喜悦与开始，无负面联想。而且它不严肃——这恰恰是「不像传统词典」
最省力的实现方式。

品牌色被刻意用得**很少**。在一个屏幕上，实心橙只出现在"此刻最该被点的那一个动作"上。

### 2.2 两种颜色，两种含义

这是整套配色里唯一需要记住的规则：

| 颜色 | 含义 | 出现在 |
|---|---|---|
| **焰橙 Flame** `--primary` | **此刻该做的动作** | 主按钮、当前进度、今天 |
| **靛紫 Violet** `--accent` | **AI 的产出** | 语境解释块、整页译文引导线、模型思考中的呼吸点 |

卡片上那条紫色竖线永远意味着"这段话是模型写的"。这条承诺曾经只在划词卡上兑现，
应用内的闪卡背面用的是品牌色——已修复，两个界面现在说同一句话。

**熟悉度阶梯里没有橙**：0 陌生红 → 1 学习中琥珀 → 2 熟悉蓝 → 3 掌握青绿。
一屏五十个词各自带着进度色，会让唯一那个真正该点的按钮彻底消失。**状态永远不用品牌色。**

### 2.3 色板

```
焰橙 Flame（品牌）
  50  #FFF1EB   100 #FFE0D3   200 #FFC6AE   300 #FF9B75   350 #FF8A5E   400 #FF7C50
  500 #FF6A3D ← 浅色主题品牌色     600 #E85426   700 #C6431A   900 #7C2A0E   950 #2A1710

靛紫 Violet（AI 标记）
  100 #F1EEFB   300 #A48BF5   500 #5B45B0   900 #1C1930

冷墨 Ink（承重色）
  0 #FFFFFF   25 #F7F7F9   50 #EFEFF3   100 #E2E2E9   200 #C9C9D4   300 #878D99
  500 #565B66   700 #3A4049   750 #2A2F39   800 #1D212A   850 #161920   900 #14161A   950 #0E1014

语义
  成功 #0C7D6F / 深色 #3DD9BE      提示 #9A5B00 / 深色 #E8A33D
  危险 #CE2C31 / 深色 #F27178      熟悉度·熟悉 #3B5BC0 / 深色 #7FA8F0
```

中性色是**冷**的。这是有意的：暖底会让橙色陷进去，冷底才托得住。暖品牌色 + 冷中性
是整套配色高级感的来源。

### 2.4 一个亮橙主色必须付的账

`#FF6A3D` 在白底上只有 **2.85:1**。这意味着它**不能当文字，不能当细线，不能当焦点圈**。
所以品牌色是三个变量而不是一个：

| 变量 | 值 | 白底实测 | 用途 |
|---|---|---|---|
| `--primary` | `#FF6A3D` | 2.85:1 | **只做填充**：按钮底、进度条、高亮块 |
| `--primary-line` | `#E85426` | 3.67:1 | 描边、图标线条、焦点圈（UI 元件门槛 3:1） |
| `--primary-ink` | `#C6431A` | 4.98:1 | 品牌色必须当文字时 |
| `--primary-text` | `#FFFFFF` | **2.85:1（自觉例外）** | 橙色按钮上的文字 |

**关于按钮文字：一条被记录在案的自觉例外。**

白字压 `#FF6A3D` 是 2.85:1，低于 AA 的 4.5。两个达标方案都试过并被否掉——

- **深墨字**（6.37:1）：数字最好看，但黑压橙是国际通用的警示配色（施工牌、化学品标签），
  放在长文旁边显得廉价。
- **加深底色到白字达标**：落点是 `#D14926`（4.50）或 `#C6431A`（4.98），都好看，
  但明显偏砖红；若只加深按钮而保留亮橙标记，同屏两个橙会读成两种颜色。

产品负责人在实际渲染的对比中选择了亮橙 + 白字。这个偏差**不隐藏**：
`tokens.test.ts` 把这一对钉在 2.85（±0.05），任何人改动品牌色都会让测试失败，
迫使这个决定被重新做一次，而不是让缺口悄悄漂移。

比例既然定死，剩下的两个杠杆是字重和字距：主按钮用 700 字重 + `0.01em`，
低对比下更容易辨认，且不花任何代价。

这条规则曾经被违反了八处——链接、焦点圈、转圈、导航选中态、朗读悬停、两处选项卡边框，
以及 popup 里「待复习」那个独立的橙色数字。
现在由 `src/styles/tokens.test.ts` 守着：任何把 `var(--primary)` 用在 `color`、
`border-color`、`outline`、`fill`、`stroke` 上的写法都会让测试失败。

### 2.5 语义色的排布是被主色挤出来的

橙做主色，语义色系统必然紧张。两处让步是明知代价而做的：

- **提示色压成深琥珀 `#9A5B00`**：亮黄橙与主色太近，用户不能分不清"品牌"和"出事了"。
- **危险色选更冷更深的 `#CE2C31`**：与焰橙拉开色相距离。

### 2.6 对比度是被验证的，不是估的

浅色与深色两套主题共 **34 组**文字/背景组合全部通过 WCAG AA（正文 4.5:1，弱化文字与
UI 元件 3:1），另有 1 组按钮文字是上面记录在案的自觉例外。`--border-strong` 是为了达标从 `#D3D3DC`（1.49）压到 `#C9C9D4`（1.64）的。

这不是一次性检查：`npm run test` 会重算全部 42 组。改任何一个颜色，测试会告诉你后果。

### 2.7 深色主题不是反转

深色下焰橙要**变亮**（`400` 而非 `500`）才能在暗面上达到同样的对比度；中性色保持冷调；
阴影加深而不是消失。深色主题与复习专注模式**引用同一批调色板 token**，物理上不可能漂移。

## 3. 字体

```
中文  PingFang SC → MiSans → 思源黑体 / Noto Sans SC → 微软雅黑
英文  Inter → -apple-system / SF Pro Text / Segoe UI
等宽  SF Mono / JetBrains Mono   （音标、复习间隔、快捷键、统计数字）
```

苹方排第一位，因为 Mac 与 iOS 用户直接拿到系统最优解、零加载；MiSans 免费商用、字重齐全，
覆盖 Windows 与安卓。**一个用户正盯着看的生词，不该等一个网络字体。**

### 字阶

| 用途 | 字号 | 行高 | 字重 | 变量 |
|---|---|---|---|---|
| 闪卡正面的词 | 28–34px | 1.3 | 700 | `--text-display` |
| 页面标题 | 22px | 1.3 | 700 | `--text-title` |
| 区块标题 | 17px | 1.4 | 600 | `--text-heading` |
| 正文 | 14px | 1.6 | 400 | `--text-body` |
| 辅助 / 译文 | 12.5px | 1.6 | 400 | `--text-small` |
| 标签 / 微文字 | 11px | 1.5 | 600 | `--text-micro` |

**中英混排**：中西文之间不手工加空格，交给字体自身的度量。标签类文字用 `0.06em`
字距加弱化色，让它退到内容之后。

## 4. 空间、圆角、阴影、动效

```
间距   4 / 8 / 12 / 16 / 20 / 24 / 32     （--space-1 … --space-8）
圆角   8 卡内元件 / 12 卡片 / 16 浮层 / 999 胶囊
折角   20px，45°，永远           （--dogear，标记的形状复用为版式元素）
阴影   --shadow-card   页面内的卡片
       --shadow-float  浮在别人页面之上的划词卡
动效   120ms 状态反馈 / 180ms 出现消失 / 320ms 卡片翻转
       缓动 cubic-bezier(0.2, 0.8, 0.3, 1)
```

**只有两级阴影**。一个阅读工具一旦堆出五级阴影就开始像后台系统。

动效上限 180ms，只做位移与透明度——**唯一的例外是闪卡翻转的 320ms**。那是品牌名里的
那个动作，必须做实，不能用淡入代替。划词卡的入场只做位移不做淡入：淡入会让底层文字
在 180ms 里透过卡片，读起来像渲染故障（这条是真踩过的）。

## 5. 界面规范

### 5.1 划词浮层（最重要的一个界面）

它出现在别人的页面上，所以它的第一职责是**不冒犯**。

- **不遮挡正在读的那句**：默认在选区下方，放不下才翻到上方，永远夹在视口内。
- **高度随可用空间伸缩**，下限 460px，上限 720px。
- **可以拖走**：自动定位大多数时候是对的，错的时候恰恰是最要命的时候。
- **Shadow DOM 隔离**，且带 `notranslate`：用户大概率同时装着别的翻译扩展。
- 信息顺序固定：基础释义 → English → **语境含义** → 原文与翻译 → 例句 → 近义词。
  语境含义带紫色左边线，因为它是这个产品存在的理由。
- 底部不显示模型名。只有"离线词典"要标明，因为它改变了这段解释可信到什么程度。

### 5.2 词卡列表

一行一个词条，密度优先。每行给出：词 + CEFR 徽标 + 音标 + 词性 / 释义摘要 /
来源域名 + 时间 / 熟悉度 + 下次复习。

**来源必须出现在列表层**，不能只在详情里——"那篇 Postgres 文章里的那个词"
是人真正的检索方式。

### 5.3 闪卡复习

复习切到**固定深色墨底**，两套主题下都一样。这是"进入专注"的仪式信号，不是主题偏好，
因此**不可配置**——一个能关掉的模式就不再意味着任何东西。

实现上，`.focus-mode` 只是在一个容器上重新声明语义 token，整棵子树随之翻转，
包括完全不知道有专注模式存在的组件。这只有在下游没有任何硬编码色值时才成立。

闪卡本身带 45° 切角，是标记的形状复用。正面只有词、音标、朗读，以及一句
"先想一想它在原句里的意思"。四个评分按钮直接显示"下次什么时候再见"——把调度器的
行为透明地摊开，用户才会信任它。

### 5.4 学习面板

只展示能从本地数据真实算出来的数字。没有"预计词汇量""学习力指数"这类无法证伪的指标。

**柱状图里只有今天穿品牌色，历史是中性色。** 十四根橙柱加一条橙进度条，会让这一屏
唯一真正的行动号召——「开始复习」——变成屏幕上最不显眼的那个橙色元素。数据不是动作。

## 6. 语气

界面文案的原则和视觉一致：**平实、具体、不邀功**。

| 写 | 不写 |
|---|---|
| 「离线词典未收录该词」 | 「暂时没有找到更多信息 😢」 |
| 「模型在写出答案前就用尽了 4000 个输出 token」 | 「出错了，请稍后重试」 |
| 「已收藏，进入复习队列」 | 「太棒了！你又前进了一步！」 |
| 「此处就是常见含义：…」 | 编造一个并不存在的语境差别 |

诚实优先于漂亮：不确定的音标返回空，不编；离线模式明确说明自己无法结合上下文，不假装。
